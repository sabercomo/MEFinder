# 《谁在害怕性别》中文 PDF↔中文 EPUB「对漏」根因：经英文基准两跳中转

2026-09-09：用户反映中文 PDF 与中文 EPUB(一比一同一译本)对照时漏配大量句子。实测定位到
**根因不是分段、不是 E5/模型、也不是同文本被门槛拒绝,而是「两跳中转对齐」**:该作品组的
基准(pivot)是**英文 EPUB**,两个中文版本各自只与英文基准对齐,二者之间**没有直接对齐**,
阅读器便把 中文PDF→英文→中文EPUB 组合成两跳路由,交集丢弃了大量段落。**直接对齐时覆盖率 100%**。

## 证据

- 作品组 `document-group-491d081a…`,`base_source_file_id` = 英文 EPUB(`epub-6ab83756…`);
  成员顺序:中文 PDF(3)、英文 EPUB(4,基准)、中文 EPUB(5)。快照内该组**只有** 中文PDF→英文EPUB
  一条 run,中文 EPUB 侧无 run。
- 路由逻辑(`text_alignment.list_alignment_targets`):无直接 run 且两端都非 pivot 时,
  `route_runs=[source→pivot, pivot→target]`,`via_source_file_id=pivot`——即经英文两跳。
- **分段并不失衡**(纠正此前基于搜索 `paragraphs` 表的错判):对齐级 `text_segments` 两侧
  几乎 1:1——中文 PDF 4000 段(中位 55 字)、中文 EPUB 3951 段(中位 54 字);屏幕那句
  「关于这类立法是如何产生的，有很多论点可以提出。」两侧都是**同一 23 字独立段**。
- **直接对齐实测**(MiniLM,用户设置;库副本上 `generate_alignment` 正式入口,离线,369s):
  - 覆盖率 **pivot 4000/4000、target 3951/3951,0 未覆盖(100%)**。
  - 3100 条链接:2665 automatic(接受)、435 rejected;形态以 **1:1 为主(2182)**,另有
    3:1(280)、1:3(224)等少量多对一。
  - 机器数据 `reports/direct-zhzh-alignment-2026-09-09.json`(仅摘要,不含正文)。

结论:同一中文译本的两个格式,**直接对齐可 100% 覆盖**;用户看到的「对漏」来自缺少直接对齐时
的英文两跳中转,与文本、分段、模型阈值无关。

## 立即可用的绕过

在「管理作品组」里选中**中文 PDF** 与**中文 EPUB** 两个版本,点「生成对照」,即产生二者的
**直接对齐**;此后阅读器对照该对将走直接 run,不再两跳中转。(此为库写操作,应由用户在自己
的正式库上执行;本轮仅在副本验证,未改动正式库。)

## 建议的产品修复(待定方向)

1. **两跳时显式提示 + 一键直接对齐**:阅读器发现当前对照走 `via_source_file_id` 路由时,
   提示「经英文版中转,完整度受限」,并提供「生成直接对照」入口。信息透明、非破坏。
2. **对齐时补齐同语言直接对**:管理作品组生成对照时,除成员↔基准外,也为同语言成员对生成
   直接 run(代价是更多计算)。
3. **改进两跳组合**:让路由组合尽量保留两跳中各自的落位(较难,且中转仍有语义损失)。

推荐方向 1(投入小、最贴合「一比一却漏配」的困惑),但需产品确认后再实现。

## 边界

- 未改动正式库、默认模型或阈值;直接对齐实测在库副本上完成。
- 435 rejected 属直接 run 内的低置信链接(如脚注/编号),非本问题主因;可另议。
