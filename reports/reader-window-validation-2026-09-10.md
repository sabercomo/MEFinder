## 2026-09-10 — 关闭死锁修复与原生进程回归

### 根因与修复

GLM 的隔离日志首次捕获了 `close_reader` 回执线程卡在 Cocoa `evaluate_js` 信号量、
解释器等待该非 daemon 线程的栈。本轮重新复现，并将关闭改成公开 `window.state`
单向通知；去掉销毁后仍要回传结果的 `close_reader` API。产品未加入延迟销毁或强制退出。

### 可重复验证

最终全量 unittest：2094 项，94.242 秒，OK（22 skip，含显式启用的原生门禁）。
原生门禁单独运行通过（1 项，2.116 秒）；Ruff F 和 Node 语法检查通过。

使用 macOS Python 3.12 / pywebview 6.2.1，项目 venv 解释器；
`tests/native_reader_window_probe.py` 使用真实阅读页面、真实 JS bridge、
`ManagedThreadingHTTPServer` 及后台的持久写入等待／关闭接口。
数据来自 `TextAlignmentTests` 临时夹具，对齐使用固定嵌入，不下载模型。
新驱动修正了旧 GLM 脚本把段落 id 当作 sourceId 的问题，实际使用文献 `epub-en`
及段落锚点 `epub-en-p0/p1`，并断言正文和当前锚点，避免将错误页面计为阅读成功。

- `--legacy-close` 仅在测试中重新暴露原关闭 API：完成 GUI/后台清理后仍不退出；
  30 秒的 faulthandler 栈与 GLM 捕获一致，父进程在 35 秒终止该测试子进程。
- 修复路径同一流程连续运行 3 次，均自然退出，退出码 0；不以清理日志代替退出断言。
- 增强原生测试通过：默认关闭时使用原弹层；开启后两窗口分别定位 p0/p1；
  第一窗口加载中文对照，第二窗口仍为单栏，关闭第二个不改变第一个的定位和对照。
- 隐藏原生窗口移动到 (80, 80)、缩放到 800 × 600 后读取实际位置／尺寸确认；
  WKWebView 的 DOM 几何确认阅读面板等于视口高度、正文底边贴合面板底边。
- 页面内关闭、系统窗口 API 关闭、关闭后重开、主窗口带两个阅读窗退出均通过。
- 便携自动化回归先失败再通过：真实 pywebview 分发器收到关闭状态时销毁窗口，
  不调用 `evaluate_js/run_js`；执行真实 `reader-window.js` 确认不再调用关闭 API。
