# PaddleOCR 本地部署验收

2026-11-24 · 0.6.6 开发工作区。CPU 路线使用 PaddleOCR 3.7.0 / PaddlePaddle 3.3.1 的 PP-StructureV3；不启用 GPU 档。

## 实测

- macOS arm64：使用 150 DPI、没有文字层的两页合成 PDF。通过应用导入接口选择 `paddleocr-local`，解析统计为本地 PaddleOCR、一篇两页；精确搜索两页不同的句子，分别返回原 PDF 第 1、2 页和字符范围。样本没有出版页码，未生成引用页码。
- macOS arm64：独立运行时使用缓存的官方依赖和模型，实际创建 Python 3.12 环境、通过推理检查并启用。从安装后的最终路径识别两页成功；卸载移除 CPU 环境及工具缓存。本次缓存命中时安装约 116 秒，不代表首次下载耗时。
- macOS arm64：另从空模型缓存测试，创建独立环境后，已从官方源下载版面和文字识别等模型；因表格模型下载慢，在约 8 分半时主动停止。关闭流程结束子进程并清理本次临时安装目录，组件未被标记为已安装，保留可复用工具缓存。首次全量下载加推理尚未跑完。
- 自部署：用 PaddleX 3.7.2 官方 PP-StructureV3 HTTP 应用在本机启动，实际连接检测和两页 PDF 请求均返回 200，识别文字吻合。该服务的 `prunedResult` 不保留 `page_index`；按[官方有序结果](https://www.paddleocr.ai/main/en/version3.x/pipeline_usage/PP-StructureV3.html)核对完整页数，有显式页索引时还须逐页连续匹配。不使用 OpenAI 兼容接口做适配。
- 设置保留既有 MinerU 模板样式和状态位置。浏览器验证保存地址、显示 PDF 导入选项、不切换默认方式；主动禁用已选的 PaddleOCR 不得暗中回退到在线解析。
- 全量 unittest 2,941 项（58 跳过，无失败）、另跑 34 项 Chrome 回归通过；Ruff、JS 语法及 `git diff --check` 通过。

## 边界

- 托管进程与已部署服务都接入现有分片导入和索引流程。首版每片至多 8 页及 32 MiB；默认官方服务仅处理批次前 10 页，不能把整书直接提交后视作完整。连接测试只使用内置合成图，外部接口限定本机或内网 IP，不经系统代理、不跟随重定向。
- Windows x64 的 Python 3.12 CPU 依赖已做解析检查，尚未在 Windows 上实际安装或运行；Linux 亦未实测。已安装环境与服务地址不随馆藏备份转移。GPU、自动解析回退、OCR 质量提升均不在本次承诺内。
