# 导入任务状态收拢核验

2026-10-13：队列写入已集中到任务服务，源码测试结果见下文；本轮不打包部署。

## 复现与边界

在改动前新增两项执行型测试，均失败：

- `test_repeated_watch_starts_only_one_request`：连续调用同一任务的监听入口，旧代码发出两次请求。
- `test_old_poll_cannot_overwrite_replacement_job`：切换到新后台任务后，旧任务的失败响应仍把队列项改为 `error`。

改动后两项均通过。`78-import-jobs.js` 是队列、上传、轮询、取消、恢复和重试的唯一写入方；导入页、书目抽屉和解析设置只读取快照或调用命令。新增架构守卫禁止其他 JS 再使用 `importStore`，并禁止服务读取 DOM / 文献库 / 解析设置。

## 行为覆盖

`tests/test_import_active_frontend.py` 执行完整服务，而非仅提取函数体：

- 入队输入和快照均与内部状态隔离，浏览器文件对象保留。
- 重复导入复用后台解析方式，合并队列行；重新解析复用已有任务，不重复监听。
- 取消中的任务保持可见，404 后移除；普通 404、网络失败、后台清理失败仍可见并报错。
- 恢复台账去重；索引失败继续时不弹付费解析确认；暂停、完成停止定时器，完成通知一次。
- 视觉 API、MinerU、本地 MinerU 切换保留接口、确认、状态及恢复标志。
- 删除或更换任务后，旧响应和定时器不再写回。

真实 Chrome 场景 `test_import_task_survives_navigation_cancels_and_resumes_after_reload` 验证：取消中仍显示并禁用删除按钮；切去搜索页后后台轮询完成取消；重新加载页面后恢复台账，索引重试直接完成。首次浏览器断言检查隐藏行的 DOM 数量而失败，已改为检查实际不可见；产品原先即在空队列时隐藏整个容器，并未把这一测试问题计为产品缺陷。
