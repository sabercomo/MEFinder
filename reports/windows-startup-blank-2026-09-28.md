# Windows 主窗口启动空白测量

2026-09-28：后端启动日志和无文献库对照均不支持把整窗浅蓝空白归因于文献数量；Windows 主窗口改为首次页面 loaded 后显示。该修改改善显示时机，不宣称缩短冷启动总耗时。

## 现场证据

- 用户反馈：主窗口先整块浅蓝约一秒，然后出现标题栏、侧边栏及主界面。
- `dist/MEFinderData/runtime/desktop.log`：16:31:13.374 → 13.435、16:31:17.483 → 17.544、16:31:53.658 → 53.716、16:33:33.957 → 34.021，均为 loading index → backend ready，分别 61、61、58、64 ms。
- 后端就绪不等于所有文献库请求完成；以上数据仅排查索引启动，不能用来断言全库检索耗时。

## 无库对照

环境：本机 Windows、项目 Python 3.12、已安装 pywebview / WebView2；0.5.7 工作树。同一进程先导入 desktop、webview、web_assets，再开始计时。HTTPServer 绑定随机本机端口，根路径返回 `render_html('frost-blue')`，其他请求立即返回 503；不创建 SearchEngine、不打开 SQLite。分别用完整主页面和一行文字 HTML 运行 `create_main_window`，在 before_show、shown、HTTP 请求、loaded 记录 perf_counter，并读取浏览器 navigation/paint 指标。

| 无库页面 | 页面字节 | 创建流程至 loaded | HTML 导航至 loadEventEnd |
|---|---:|---:|---:|
| 完整主页面 | 1,508,918 | 750.5 ms | 115.4 ms |
| 一行文字 | 57 | 704.2 ms | 20.5 ms |
| 完整主页面，初始隐藏 | 1,508,918 | 795.7 ms | 104.0 ms |

完整页面重复三次：创建流程至 loaded 为 768.8、796.1、763.2 ms；窗口原生创建约 406.5–446.7 ms，随后约 209–225 ms 才发出 HTML 请求。以上不是双击至界面出现时间，未含模块导入、打包解压或真实文献库请求；系统文件缓存未控制，不能代表不同机器，也不能证明相比旧版回归的原因。

另对浏览器持久缓存做三次探索：743.9、766.1、782.2 ms，与默认私密模式范围重叠；未据此修改产品 private_mode。

## 结论与修改边界

- 事实：不连接文献库仍有桌面壳/浏览器初始化等待；原流程先显示原生底色，再加载网页。
- 推断：用户所见整窗空白主要处于网页首屏之前，不是文献数量单一解释。没有相同环境下旧版对照，不能解释所有历史差异。
- Windows 创建主窗口时 hidden=True，首次 loaded 回调显示一次。加载页、错误页同样适用；后续导航/刷新不再次 show，避免抢回焦点。macOS 维持原流程。
- loaded 表示页面和桥接就绪，不是屏幕像素提交完成；仍可能有短暂绘制间隔，不宣称绝对零闪烁，也不把延后显示当作性能提速。
- 回归测试覆盖三个入口、首轮 loaded 不干扰其他订阅者、后续加载不重复显示。测试名：`test_windows_main_window_waits_for_page_then_shows_only_once`，修复前三个子场景均失败，修复后通过。
- 本轮未重建或替换用户的 dist 可执行文件、安装包、便携包或 GitHub Draft 资产。
- 验证：桌面专项 62 项通过；全量 unittest 2609 项 OK（36 skip，200.155 s），Ruff 零告警，前端装配守卫随全量通过；没有修改网页资源，指纹无需更新。
