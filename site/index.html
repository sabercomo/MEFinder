PDF · Word · EPUB 本地文献原句与页码定位

找到原句，
给你书内实际页码。

不是 PDF 物理页码。PDF 第 69 页，书上印的是序言第 16 页。

文献原句定位器（MEFinder）是一款本地优先的文献原句检索、页码定位与引文辅助工具。完整句子、残缺片段、带着错字的记忆都可以交给它：它在你自己的文献库里找回原文，标出书内实际页码，再把出处排成你要的格式。

页码

引用的是书内实际页码，不是 PDF 物理页码

PDF 阅读器显示的页数从封面算起，序言、目录、插页都占页数，和书上印的页码对不上。MEFinder 的每条检索结果都带着书内实际页码。

  • 自动映射。读取页边印着的页码序列，把每个 PDF 物理页对应到书内页码；序言用罗马数字、正文用阿拉伯数字这样的分段也能分开认。
  • 人工分段校准。自动映射不准的书，按段指定「PDF 第几页是书内第几页」，之后整段跟着改。
  • EPUB 只用出版方页码。读取出版方提供的 page-list / pagebreak，绝不按屏幕排版生成页码。
  • 没有就说没有。找不到书内页码时如实标「页码尚未解析」，不推算、不补数。

功能

从收书到出处，六步都在本机

01

收书

PDF、Word、EPUB 直接进库，文本型文件在本机解析。扫描件、乱码文本层和复杂版面，才由你决定是否交给 MinerU 或其他视觉 API。

Zotero 分类可以只读同步过来；换设备时导出 .mefinder.zip 文档包，重新导入即可，不必重跑 OCR。

02

文献库

每本文献带上作者、译者、出版社、页数和页码状态。书目待补全、页码待处理单独列在底部，点进去就能处理；同一部作品的不同版本在这里互相关联。

可按来源、格式和文献范围筛选，也可把指定页按原书页码或 PDF 物理页码导出成 Markdown。

03

找回原句

五种模式：自动、精确、忽略空格、忽略标点、模糊。残缺的半句话、记混的译名、OCR 留下的错字都能命中，旁边就是它引用的那一页。

繁简统一检索默认开启：用简体关键词命中繁体原文，结果与导出保留原文写法。

04

结构化阅读

从命中处直接打开结构化文本，读命中段落和相邻内容，也能翻回原始 PDF 页面。目录读取已入库的一、二级标题。

可在设置里开启独立阅读窗口，让阅读与对照单独移动、缩放；关闭时仍在主窗口内读。

05

译本对照

把同一部作品的原文与译本、或不同版本归入作品组，选两版逐段对齐，双栏对照阅读，在版本之间定位对应文字。对齐在本机完成。

两栏跟随滚动，对齐的段落用琥珀色框出，选中即可复制引文。页码按栏各自标注：英文原书有出版方页码，中译本没有，就显示「页码尚未解析」。置信度偏低的段落旁标「!」，可以人工指定对应的译文段。首次生成对齐前，要在设置里联网安装一次计算组件（约 94 MiB）和跨语言模型，之后计算全程离线。

06

出处与引文

识别并补全书目信息，把出处一次排成中文脚注、GB/T 7714、APA、MLA 或 Chicago。已配对的脚注随正文带出。

出处里的页码就是书内实际页码，和上面「页码」一节是同一套数据。

MCP

接入你自己的 Agent

MEFinder 自己不接大模型，也不生成回答。它提供的是一个本地 MCP 接口：发布包里附带 MEFinderMCP（Windows 安装版、绿色版和 macOS 版都有，不用另装 Python），你把它配进自己在用的 Agent，比如 Claude Code、Codex、WorkBuddy，Agent 就能调用 17 个工具查你的文献库。用哪个 Agent、哪个模型、哪个账号，都是你那边的事，和 MEFinder 无关。桌面端不必开着，MCP 进程本身不联网。

Agent 拿到的不是 PDF 原件，而是 MEFinder 解析好、存进库里的结构化结果：原文、文献和段落 ID、PDF 页码、书内引用页码，以及这个页码是怎么来的。查到的句子可以直接回到原书那一页核对。

给 Agent 的是 JSON，不是 PDF

直接让 Agent 读 PDF

  • 每次提问都要从 PDF 现场抽文字，扫描件还得先 OCR
  • 文字按版面抽出来，双栏、脚注的先后要 Agent 自己理顺
  • 只知道是 PDF 第几页，书上印的页码要 Agent 自己推
  • 几百页的书整本塞进对话，很吃上下文

让 Agent 读 MEFinder 的 JSON

  • 导入时解析一次，版面复杂的可以选 MinerU，之后读的都是现成结果
  • 按页或段落切好，每块有自己的 ID，前后文单独给
  • PDF 物理页和书内引用页分开给，还标明页码是否校准、怎么映射的
  • 只取命中处前后几页，用不着整本塞进去

verify_quotes · diff_quote

定稿前核对引文

把正文里的引文交给 Agent，它一次批量比对，每条标出 verified（逐字一致）、approximate（相近，可能抄错）或 not_found（库里没有）。相近的几条再和原句逐字对齐，多了、漏了、改了哪几个字都会标出来。

下面这五条引文，原书里是这么写的吗？

locate_quote · verify_quotes

核对笔记里的引文

Agent 用它自己的文件权限读笔记，比如 Obsidian 里的某一篇，再把其中的引文逐条交给 MEFinder：原句在不在、页码对不对、上下文有没有被截断。MEFinder 不读也不改你的笔记文件。

这篇笔记里的引文，哪些和原书对不上？

find_parallel_passages

找译文对应的原文

给一句中译，指定要找的语言，比如英语、德语，返回原书里对应位置的几个候选和前后文，候选来自作品组已经生成的对齐。Agent 比较语义、专名和引文结构后再确认；合理的候选不止一个时，它会全部列出，不替你挑。反过来，给一句原文找中译也行。

这句中译在德文原书里对应哪一句？

find_parallel_passages · locate_quote

笔记里给译文配上原文

读中译本记笔记时，让 Agent 在每条引文下面附上原文和原书页码：先定位中译引文的出处，再找它在原书里的对应句。候选不唯一的地方，Agent 会标出来留给你挑，不会随手配一句。

给这篇笔记里的中译引文都配上英文原文和页码。

search_passages · read_document_window

读书、整理材料

只记得大意时，先按相关性召回段落，再逐字定位。读一本书时按需取前后几页，不必把整本塞进对话。笔记由 Agent 写，写得对不对，仍以书里的原文为准。

邪修用法

不按说明书来的几种接法

下面这些不是 MEFinder 设计时的主要用途，是身边的人自己摸出来的，效果没有专门验证过，照做之前先拿几本书试一试。

  1. 工科：把 Zotero 里的论文整批拿去蒸馏

    有位工科朋友的文献都攒在 Zotero 里，可 Zotero 把每篇 PDF 各放在一个单独的文件夹里，想整批交给 Agent 很麻烦。他是这么接的：

    1. 在「设置 → 来源 → Zotero」勾选分类，论文直接导进 MEFinder
    2. PDF 解析方式选「强制 MinerU」，图表和公式多的论文解析得更干净
    3. 接上 MCP，让 Agent 读带文献 ID 和页码的 JSON 结果，开始蒸馏

  2. 文科：让 Agent 替你读书做笔记（不是）

    书还是得自己读。Agent 能做的，是先把带页码的原句一段段摘出来，你读的时候对着核，写笔记时引文和页码都是现成的。

边界

数据在哪里，以及它不做什么

索引、检索、页码映射、对齐和大部分元数据处理都在你本机完成，文件留在原处，数据库是一个你自己能备份的 SQLite 文件。没有账号，没有云端同步，没有遥测上传你的阅读记录。下面这几条是设计约束，不是待补功能。

  • 不猜出处。没找到就是没找到，它不会给一个像模像样的答案。
  • 不虚构页码。EPUB 只用出版方给的页码表；没有就标「页码尚未解析」——上面的演示里就能看到一条。
  • 不默认联网。检索、索引、页码映射、对齐计算和本机 OCR 都在本机完成。会联网的只有这几件事，都要你手动发起：把 PDF 交给 MinerU 或其他视觉 API 解析；「查图书信息」这类题录查询；首次安装对齐组件、模型和本机 OCR 组件；检查软件更新。
  • 不扩成知识库。它的定位是找回原句与核对引文，不做笔记工作台、文献计量或推荐内容。
  • 不动你的 Zotero。只读取本机接口，增删与题录以 Zotero 为准。

缘起

为什么做这个

作者是文科在读硕士。写小论文时，每到定稿前都要把正文里的引文一条条重新核对：原文有没有抄错，出处有没有写对，页码准不准，对上下文的理解有没有偏差。写大论文时文献更多了，于是一遍遍在几个 PDF 之间打开、搜索、翻页、核对。

找了一圈没有贴合这种需求的软件，就自己做了一个。这也是第一次完整做完一个软件项目，很多东西边做边学。如果它没找到你确定存在的句子，或者页码、题录处理得不对，欢迎附上具体样例提 Issue。
