# 文献原句定位器 v0.5.5（迭代中）

> 2026-09-17：**迭代中,未发布**。0.5.5 是「对齐计算组件化」版本——把译本对齐所需的数值计算栈(NumPy / ONNX Runtime / fastembed,约 94 MiB)从主程序里移出,改为按需安装的独立运行时。已落地:**主包精简闭环**(桌面主包定向构建 206.4 → 100.8 MiB,macOS ARM 实测,不含 sidecar);**MCP sidecar 精简**(sidecar 独立由 77.9 → 45.9 MiB,即分发包里第二份数值栈);**设置页安装管理界面**(译本对齐的安装 / 重试 / 升级 / 卸载 / 任务占用等待 / 取消,含卸载删模型保留成果的确认)。**尚未完成**(见文末):Windows / macOS Intel 冻结验证、从精简正式包出发的真机安装—离线对齐端到端闭环。当前结论:组件化的代码闭环与 macOS ARM 证据齐备；正式交付仍等待跨平台冻结验收。

## 更新内容

### 译本对齐改为按需组件,主程序更小

- 桌面主程序不再打包对齐计算数值栈;安装包体积显著下降(macOS ARM 定向构建实测约减半)。检索、阅读、题录、已有对齐结果与引用定位不受影响,均不依赖该栈。
- 译本对齐的嵌入计算与模型探针改在**独立解释器**中运行;计算源随应用交付,由独立运行时的解释器加载。
- 未安装独立运行时时,译本对齐会**明确显示不可用原因**(而非静默失败或误报);已生成的对照与人工修正保留可用。

### 设置页新增对齐计算组件的安装管理

- 「译本对齐」设置页新增「独立计算运行时」卡片:未安装可**安装**、失败可**重试**、有新版可**升级**、已装可**卸载**,安装/升级/卸载进行中可**取消**;当前有对齐任务在跑时,升级/卸载会显示「任务结束后…」并等待。
- 自带数值栈的老用户(无需单独安装)不受打扰,卡片保持隐藏;精简包缺栈或已装独立运行时时才呈现管理入口。
- **卸载确认如实呈现规则**:卸载会删除运行时及其所属的对齐模型文件,但**文献、已有对齐成果与人工修正都会保留**——不再笼统写「模型保留」。

### MCP sidecar 精简

- MCP sidecar 只读已有对齐、不做对齐计算,不再重复携带数值栈:独立可执行由 77.9 MiB 降到 45.9 MiB(macOS ARM 实测)。这份收益独立于桌面主包——sidecar 是分发包里的第二份数值栈,主包缩小的数字不代表整分发收益。工具行为不变。

## Bug 修复

- 修复安装依赖版本冲突、维护中断后无法再计算、下载中卸载留下半成品和退出后下载进程残留。Windows 与 POSIX 共用跨进程使用／维护锁语义。
- 旧缓存缺少对齐组件定义时使用内置清单；详情及实际计算证据见 [审计修复报告](../reports/alignment-runtime-review-fixes-2026-09-16.md)。

- 精简主包下触发模型下载时,若未安装独立运行时,给出明确的「运行时未安装」提示,替代原先会抛出的底层 `ImportError`。
- 修复设置页读取对齐运行时状态时,把成功响应里表示「上次操作失败」的业务字段误判为请求失败(会错显「读取失败」、掩盖真实的「安装失败/重试」态);现只按 HTTP 状态码判定请求成败。
- 更正 v0.5.4 体积盘点报告中「numpy 全部函数内 lazy import」的表述:实为 3 处 `TYPE_CHECKING` 守卫 + 1 处零引用的模块级导入(详见 `docs/issues/note-alignment-compute-runtime-2c.md`)。
