# 文献原句定位器 v0.5.5（迭代中）

> 2026-09-19：**迭代中,未发布**。0.5.5 是「对齐计算组件化」版本——把译本对齐所需的数值计算栈(NumPy / ONNX Runtime / fastembed,约 94 MiB)从主程序里移出,改为按需安装的独立运行时。已落地:**主包精简闭环**(桌面主包定向构建 206.4 → 100.8 MiB,macOS ARM 实测,不含 sidecar);**MCP sidecar 精简**(sidecar 独立由 77.9 → 45.9 MiB,即分发包里第二份数值栈);**设置页安装管理界面**(译本对齐的安装 / 重试 / 升级 / 卸载 / 任务占用等待 / 取消,含卸载删模型保留成果的确认)。**尚未完成**(见文末):Windows 完整组件链 / macOS Intel 真机验证、首次模型联网下载与正式分发包验收。本轮复审已修复安装状态同步与取消边界,补齐 macOS ARM 定向冻结包真实运行时安装、复用模型的离线计算和卸载保留成果证据。当前结论:本机代码门禁与上述 ARM 闭环通过；正式交付仍等待跨平台冻结验收。

## 更新内容

### 章节目录与双语跳转

- 阅读器工具栏新增「目录」，按原有层级展示已入库的一、二级标题，支持方向键、Enter 和 Escape。
- 点击章节高亮左栏标题，右栏按现有对齐关系定位；即使暂停跟随也同步一次，之后保持暂停。没有对应位置时清除旧高亮，保留右栏原位置并说明原因。
- PDF 复用 Markdown 导出的标题可信性校验，EPUB/Word 使用已入库标题样式；不重解析原文件、不生成虚构页码。缺少标题数据的旧文献显示空目录说明。
- 新增只读 `/api/document/outline?source_id=…`；契约与验收见 `docs/issues/reader-chapter-navigation.md`。

### 双语阅读审核修复

- 修复多源分段链接的人工校正在滚动定位时被绕过、过期请求重新打开已关闭对照、新对齐结果未刷新链接缓存三项问题。
- 跟随只移动右栏，不再把左栏拉回搜索命中；定位成功清除旧错误提示。默认仍为左栏驱动右栏，算法与 batch64 不变。
- 回归与真实书库副本的浏览器证据见 `reports/translation-reader-review-2026-09-18.md`。此项修复后已补章节目录，见上节。

### 译本对齐改为按需组件,主程序更小

- 桌面主程序不再打包对齐计算数值栈;安装包体积显著下降(macOS ARM 定向构建实测约减半)。检索、阅读、题录、已有对齐结果与引用定位不受影响,均不依赖该栈。
- 译本对齐的嵌入计算与模型探针改在**独立解释器**中运行;计算源随应用交付,由独立运行时的解释器加载。
- 未安装独立运行时时,译本对齐会**明确显示不可用原因**(而非静默失败或误报);已生成的对照与人工修正保留可用。

### 设置页新增对齐计算组件的安装管理

- 「译本对齐」设置页新增「独立计算运行时」卡片:未安装可**安装**、失败可**重试**、有新版可**升级**、已装可**卸载**,安装/升级/卸载进行中可**取消**;当前有对齐任务在跑时,升级/卸载会显示「任务结束后…」并等待。
- 自带数值栈的老用户(无需单独安装)不受打扰,卡片保持隐藏;精简包缺栈或已装独立运行时时才呈现管理入口。
- **卸载确认如实呈现规则**:卸载会删除运行时及其所属的对齐模型文件,但**文献、已有对齐成果与人工修正都会保留**——不再笼统写「模型保留」。

### MCP sidecar 精简

- MCP sidecar 只读已有对齐、不做对齐计算,不再重复携带数值栈:独立可执行由 77.9 MiB 降到 45.9 MiB(macOS ARM 实测)。这份收益独立于桌面主包——sidecar 是分发包里的第二份数值栈,主包缩小的数字不代表整分发收益。工具行为不变。

### 译本对照改版：作品—版本页与统一阅读器

- 左侧栏新增「译本对照」（在「文献库」之后）。对齐组件未安装时不显示入口；已卸载但有已有对齐时显示并标「只读」，可以阅读，生成类按钮禁用并就地说明原因、给出重新安装入口。
- 「译本对照」页：左栏作品列表与搜索、同名归组建议（核对 / 忽略）；右栏作品页含「继续阅读」、版本清单（版本名、书名 · 格式、语言、出版、页码来源，「未校准」用警告色）与底部对照栏。最多勾选两个版本，勾第三个替换最早勾的。状态措辞只陈述后端事实：直接对齐 · 已匹配段落 N% · N 处待检查 / 间接关联 · 经「基准」换算 / 需重新对齐 · 模型已更换，旧结果可读 / 尚未对齐 / 生成中。
- 「管理版本」抽屉：改作品名、设基准（会删除已有对齐时先确认）、行内改版本名、移出、从文献库搜索添加版本、每对版本的对齐状态与生成 / 生成直接对齐 / 重新对齐 / 取消、删除作品（界面先隐藏，提示条带「撤销」，提示消失后才真正删除；对齐与人工校正随之删除，文献保留）。
- 文献库：移除工具栏「全部文献 / 按作品组」下拉、「管理作品组」弹窗与「加入作品组」下拉；多选后改为「加入作品…」弹窗（自绘下拉选择新建或已有作品，新建时第一本为基准；已在其他作品里的书提示后移过来）。完成后不跳转，提示条带「前往译本对照」。已归组的文献行显示作品名链接；详情抽屉新增「阅读」。
- 同名归组核对：对照表列出书名、作者、格式、篇幅、页码并标出不一致项，按钮为「不是同一作品 / 稍后 / 归为一部作品」；「不是同一作品」持久记住。
- 统一阅读器：检索、文献库、译本对照进入同一个阅读器，主窗口内占满内容区（不再是大弹窗），应用侧栏收成图标栏、返回时恢复，返回按钮写来源。工具栏：返回、左栏版本下拉、「添加对照版本」（列出其他版本与对齐状态，底部「管理版本…」）或交换 / 右栏版本 / 关闭对照，跟随滚动开关、复制引文、「⋯」（跳到页、在作品中查找、在新窗口打开 / 回到主窗口、显示页眉页脚、管理版本）。原「阅读 | 译本对照」分段切换移除。
- 正文改为连续段落排版（18px、行距 1.85，只在页码变化处标页码），两栏各自保留来源与页码锚点；直接对齐两栏间为细实线，间接关联为虚线并在顶部说明。点一段原文高亮其对应段。选中尚未对齐的版本时右栏原位显示「生成对齐」，左栏照常阅读。
- 低置信段落（算法给出对应但置信度低于门槛）旁有「!」：可多选候选译文段保存一对多校正、标记「译本无对应」或「暂不处理」（「!」变灰保留）。没有对应的段落不标「!」。
- 阅读位置按作品保存版本对与位置，「继续阅读」用 PDF 页序或段落序号如实表述，不冒充印刷页码。

### 译本对照改版：后端存储与接口

- 数据库 schema 升到 v7(附加迁移,只新增表):`document_group_reading_positions`(每部作品上次阅读的版本对与位置,锚点为条目序号 + 码点偏移,不存页码)、`alignment_review_deferrals`(低置信段落「暂不处理」)、`document_group_suggestion_dismissals`(同名归组建议「不是同一作品」)。**v7 库无法再被 0.5.5 之前的版本打开**(旧版会拒绝更高 schema)。
- 新接口:`/api/translation-works/overview`(每对版本的直接 / 间接 / 未对齐状态、已匹配段落比例、待检查数、模型或算法变更)、`/api/text-alignments/links`(阅读器按页或段落范围读取逐段对应关系)、`/api/text-alignments/review-candidates`、`/api/text-alignments/corrections/save|defer`、`/api/translation-works/reading-position`、`/api/translation-works/suggestion-dismissals|dismiss-suggestion`、`/api/document-groups/move-members`、`/api/text-alignments/current`。契约见 `docs/contracts/v0.5.5-http-api.json`。
- 人工校正支持一对多与「译本无对应」(空目标的已确认校正,定位时明确返回无对应,不退回算法结果)。应用内校正视为用户直接确认;MCP 的提议—确认—撤销流程不变,提议仍须给出目标段落。
- 「已匹配段落」只统计基准一侧被算法接受的段落比例,不代表对应准确。
- 批量加入作品在一个事务内完成:一本书只属于一个作品,从原作品移入时删除该书在原作品中的对齐,原作品变空则删除。
- 对齐计算进程只上报开始与结果,没有批次进度,「生成中」暂不显示百分比。

## Bug 修复

- 补齐启动缓存边界：请求失败后可重试；加载过程中删除文献或恢复备份，旧请求不能将缓存标为有效，结束后补拉新快照。新增执行真实 JS 的异步回归覆盖。

- 修复启动后文献库与译本对照要等数秒才显示。两处原因:① 0.5.5 改版把 `/api/translation-works/overview`(实测真实库冷态约 2.4 秒,启动接口里唯一的秒级查询)塞进了启动序列,并在单线程 HTTP 服务上把并行的文献库摘要请求拖慢近十倍——现改为启动只拉毫秒级的可用性判断点亮侧栏入口,总览延后预取;`works.load` 加已加载门与在途去重(切换页面不再重付秒级查询),删除文献或恢复备份后经 `invalidate` 重置。② 0.5.4 起「自动匹配阈值」滑杆程序性回填时 `dispatch` 合成 `input` 事件,触发 inline `oninput` → 保存偏好 → 再回填的递归,每轮启动向服务连发约 87 个写偏好的 POST(每个都写盘)——现改为就地补滑杆填充,值未变化不写偏好。验证基于 9 月 11 日真实库副本的 serve 实测(接口计时、并发争用、请求体抓取),修后 POST 风暴归零、切页零重发。

- 第二阶段复审：修复安装/卸载后计算与模型状态不刷新、旧请求覆盖安装状态、首次读取失败无恢复入口，以及不支持/不兼容组件误报可用。修复安装取消被改写为失败、验证后取消仍发布与 uv 下载进度沿用的问题；新增 10 项回归，全量 2369 项（23 跳过）通过。详见 [本轮审核报告](../reports/alignment-phase2-review-2026-09-17.md)。

- 修复安装依赖版本冲突、维护中断后无法再计算、下载中卸载留下半成品和退出后下载进程残留。Windows 与 POSIX 共用跨进程使用／维护锁语义。
- 旧缓存缺少对齐组件定义时使用内置清单；详情及实际计算证据见 [审计修复报告](../reports/alignment-runtime-review-fixes-2026-09-16.md)。

- 精简主包下触发模型下载时,若未安装独立运行时,给出明确的「运行时未安装」提示,替代原先会抛出的底层 `ImportError`。
- 修复设置页读取对齐运行时状态时,把成功响应里表示「上次操作失败」的业务字段误判为请求失败(会错显「读取失败」、掩盖真实的「安装失败/重试」态);现只按 HTTP 状态码判定请求成败。
- 更正 v0.5.4 体积盘点报告中「numpy 全部函数内 lazy import」的表述:实为 3 处 `TYPE_CHECKING` 守卫 + 1 处零引用的模块级导入(详见 `docs/issues/note-alignment-compute-runtime-2c.md`)。
