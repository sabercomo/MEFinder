# v0.5.5 人工正文范围提交

2026-09-20：提交范围必须同时携带两本书在编辑时的分段集标识；解析文本变化时拒绝旧范围。

适用于 `POST /api/text-alignments/start` 与 `POST /api/text-alignments/generate`。
沿用既有作品 ID、两侧文献 ID 和 `force` 字段，以下两个字段必须同时提供或同时省略：

```json
{
  "reviewed_body_ranges": {"pivot": [4, 12], "target": [2, 8]},
  "expected_segment_set_ids": {"pivot": "segment-set-…", "target": "segment-set-…"}
}
```

- `reviewed_body_ranges` 使用半开区间 `[start, end)`，界面显示的末段序号在提交时加一。
- `expected_segment_set_ids` 的两侧值必须为非空字符串，原样取自
  `POST /api/text-alignments/body-range` 的 `sides[].segment_set_id`，不能自行推算。
- 缺少一侧、字段不成对、类型错误或区间非法时，返回 HTTP 400。
- 准备对齐时，在同一写事务中获取当前两侧分段集并比较标识。任意一侧不一致，返回
  `文献解析文本已更新，请重新加载正文范围后再提交`，不计算、不写入新的对齐运行或范围。
  `/generate` 直接返回 400；`/start` 返回 202 后，由任务状态接口返回此 400 终态。
- 同时省略两个字段时，保持普通自动对齐行为：只复用当前两侧分段集对应的既有人工范围。
- Python 内部实验调用仍可直接提供 `reviewed_body_ranges`；编辑 UI 的跨请求提交必须通过上述版本校验。

验证：`tests.test_alignment_body_range`、`tests.test_text_alignment_controller`、
`tests.test_text_alignment_coordinator`；界面回归脚本 `scripts/check_body_range_ui.cjs`。
