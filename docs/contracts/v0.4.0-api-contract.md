对照基线：v0.3.8 后端；分块上传以 `bcd0a74` 为保留基线

## 1. 状态说明

- `已实现`：存在于后端检查点 `87f6541`。
- `待汇合`：已经存在于 Claude 使用的前端分支及 v0.3.8 分块上传提交，但尚未合入后端检查点。
- `兼容保留`：旧调用方式继续可用，前端可以逐步迁移。

当前后端检查点与 v0.3.8 相比，没有新增或删除业务领域端点。最终 v0.4.0 必须保留四个分块上传传输端点；它们不是新的业务能力，而是 Windows WebView2 的有界内存上传协议。

## 2. 新增／待汇合端点

### 2.1 `POST /api/import-upload/start`（待汇合）

用途：创建有界内存的上传会话。

JSON 请求：

```json
{
  "file_name": "example.pdf",
  "size": 12345678,
  "parse_mode": "auto",
  "provider_id": ""
}
```

字段：

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| `file_name` | string | 是 | 仅 `.pdf`、`.docx`；兼容别名 `filename` |
| `size` | integer | 是 | 大于 0；总大小不限，正文通过分块接口传输 |
| `parse_mode` | string | 否 | `auto`、`mineru`、`vision`；默认 `auto` |
| `provider_id` | string | 条件必填 | `parse_mode=vision` 时必须提供 |

成功：HTTP 200

```json
{
  "ok": true,
  "upload_id": "32位小写十六进制字符串",
  "chunk_size": 4194304,
  "total_size": 12345678,
  "file_name": "example.pdf"
}
```

错误：

- 400：请求不是对象、文件名/类型/解析方式无效、无法创建临时文件。
- 413：文件为空，或上传控制 JSON 超过 64 KiB。
- 500：无法创建上传会话的未预期错误。

### 2.2 `POST /api/import-upload/chunk`（待汇合）

用途：追加一个原始二进制分块。这个端点不是 JSON，必须在通用 JSON 大小检查之前路由。

请求头：

| 请求头 | 类型 | 约束 |
| --- | --- | --- |
| `X-Upload-ID` | string | `/start` 返回的 32 位 ID |
| `X-Upload-Offset` | integer | 必须严格等于服务端当前 `received_size` |
| `Content-Length` | integer | `1..8 MiB` |
| `Content-Type` | string | 任意二进制类型均可 |

请求体：原始文件分块。

成功：HTTP 200

```json
{
  "ok": true,
  "upload_id": "...",
  "received_size": 4194304,
  "total_size": 12345678,
  "complete": false,
  "first_chunk": true
}
```

错误：

- 400：ID、offset、长度或分块正文无效/不完整。
- 404：上传任务不存在或已过期。
- 409：offset 不连续；响应错误文字会给出应继续的字节位置。
- 413：单块超过 8 MiB，或累计数据超过声明的文件大小。
- 500：分块写入的未预期错误。

### 2.3 `POST /api/import-upload/finish`（待汇合）

JSON 请求：

```json
{"upload_id": "..."}
```

成功后进入原导入任务管线，响应与兼容端点 `POST /api/import` 一致：

```json
{
  "ok": true,
  "job_id": "import-...",
  "file_name": "example.pdf",
  "source_file_id": "pdf-import-...",
  "detected_pdf_type": "native_text",
  "parse_route": "native",
  "provider_id": null
}
```

说明：DOCX 的 `detected_pdf_type`、`parse_route`、`provider_id` 可以为 `null`。

错误：

- 400：请求不是对象、导入参数/文件处理无效。
- 404：上传任务不存在或已过期。
- 409：尚未传完、临时文件丢失或最终大小校验失败。
- 413：上传控制 JSON 超过 64 KiB。
- 500：完成导入的未预期错误。

### 2.4 `POST /api/import-upload/cancel`（待汇合）

JSON 请求：

```json
{"upload_id": "..."}
```

成功：HTTP 200

```json
{"ok": true, "cancelled": true}
```

`cancelled=false` 表示格式有效，但会话已不存在；无须将其当成失败。

错误：

- 400：请求不是对象或 `upload_id` 格式无效。
- 413：上传控制 JSON 超过 64 KiB。

## 3. 已改动端点与语义

### 3.1 所有 JSON `POST /api/*`（已实现）

- 新增通用请求体上限：1 MiB。
- 超限返回 HTTP 413：

```json
{"error": "JSON 请求内容过大。"}
```

- 原始文件端点 `/api/import` 和 `/api/import-upload/chunk` 不走该 JSON 上限。
- 原有更小的专用上限继续适用：引文 16 KiB、部分题录请求 32 KiB、上传控制请求 64 KiB。
- 应用开始关停后，新的 POST 返回 HTTP 503：

```json
{"error": "应用正在关闭。"}
```

### 3.2 `POST /api/search`（已实现）

请求字段没有新增或删除：

| 字段 | 类型/默认值 |
| --- | --- |
| `query` | string，默认 `""` |
| `mode` | string，默认 `"auto"` |
| `limit` | integer 或 `"all"`；字符串 `"0"` 也表示全部；非法值回退为 10 |
| `source_type` | string，默认 `"all"` |
| `source_file_id` | string 或 null |

变更：

- 顶层 JSON 非对象时，稳定返回 HTTP 400：`{"error":"搜索请求必须是 JSON 对象。"}`。
- `match_start` / `match_end` 明确为 Unicode codepoint 的半开区间 `[start, end)`。
- NFKC 组合字符、兼容展开、PDF 断行连字符的命中会映射回完整原文区间。
- `page_match_spans[*].page_char_start/end` 同样是物理页 Unicode codepoint 半开区间。
- 去重身份改为 `(source_file_id, paragraph_id, match_start, match_end)`；不同段落中的相同文字会分别返回。
- 真正横跨两个物理页的 CROSS 命中不再因某页出现相同文字而被删除；只删除映射到完全相同物理页字符区间的单页 helper 重复项。

没有新增或删除搜索响应字段，但相同查询的结果数量、顺序及高亮边界可能因上述正确性修复而变化。

### 3.3 `GET|HEAD /source/{source_file_id}`（已实现）

- 完整请求仍返回 HTTP 200，但正文改为流式发送，不再一次性读入内存。
- 新增单一 `Range: bytes=...` 支持：
  - HTTP 206；
  - `Accept-Ranges: bytes`；
  - `Content-Range: bytes start-end/total`；
  - 正确的 `Content-Length`。
- 支持 `start-end`、`start-` 和 `-suffixLength`。
- 多范围、格式错误、空文件范围或不可满足范围返回 HTTP 416：
  - `Content-Range: bytes */total`；
  - `Content-Length: 0`；
  - 无 JSON 正文。
- `HEAD` 使用与 `GET` 相同的状态和响应头，但不发送正文。

### 3.4 导入任务状态（已实现）

队列现在有界：2 个 worker、最多 32 个待处理任务。队列饱和或关停时，已安全登记的普通导入任务不会丢失，而会出现以下公开状态值：

```json
{
  "status": "failed",
  "phase": "queue_failed",
  "failure_stage": "queue",
  "can_resume": true,
  "message": "导入任务暂时无法进入处理队列。文件和任务进度已安全保留，可点击“继续导入”重试。"
}
```

这些字段通过 `/api/import-status` 和 `/api/import-resumable` 暴露。前端必须按枚举值判断，不应依赖中文 `message`。

当前各入口的队列饱和 HTTP 行为并不完全相同：

- 普通导入/重试：创建任务成功，HTTP 仍为 200；随后任务状态为 `queue_failed`。
- `/api/bibliographic-metadata/batch-detect`：HTTP 503，并返回 `error` 和 `job_id`。
- `/api/backup/import`：当前返回 HTTP 400 和 `error`；前端只需作为通用失败展示，不要据此区分业务错误。

### 3.5 数据迁移、备份恢复、页码与元数据写入（已实现）

公开请求/响应字段没有变化。变更仅涉及并发与持久化保证：

- 已开始的配置 + SQLite 操作会完成提交或回滚后再退出。
- 备份恢复与索引重建互斥，不再覆盖并发元数据修改。
- 数据迁移与已登记的导入任务/重建互斥，并在一致性区内再次检查活动任务；上传尚未登记为任务的窗口由最终分块上传汇合门禁继续收口。
- 自定义 `index_path` 的重建会更新该活动数据库，不再误写固定的 `data/index.sqlite3`。

原有活动任务冲突仍返回 HTTP 409；其他既有 400/500 语义不变。

无。

## 5. 端点删除与兼容性

- 删除端点：无。
- `POST /api/import`：兼容保留，仍接受整文件原始正文及原请求头；新前端应优先使用分块上传。
- `/api/search`、`/api/import-status`、`/api/import-resumable`：路径与基本响应结构保持兼容。
- 未新增公共 `error.code` 字段；除既有题录查询外，前端应以 HTTP 状态 + `error` 文本作通用处理，以任务枚举字段作稳定业务判断。

## 6. HTTP 状态码变化汇总

| HTTP 状态 | 新增/扩展场景 |
| --- | --- |
| 400 | 搜索顶层 JSON 非对象；上传参数、ID 或分块正文无效 |
| 404 | 分块上传会话不存在或已过期 |
| 409 | 分块 offset 不连续、上传未完成/最终校验失败；活动任务阻止数据迁移 |
| 413 | JSON 超过 1 MiB；上传控制超过 64 KiB；分块超过 8 MiB；文件为空 |
| 416 | `/source/{id}` 的 Range 格式错误、多范围或不可满足 |
| 500 | 上传/导入的未预期错误 |
| 503 | 应用关停拒绝新 POST；批量元数据任务队列饱和；搜索期间索引正在重建（既有语义） |

## 7. 最终汇合的强制验收项

1. `/api/import-upload/chunk` 必须在通用 1 MiB JSON 读取/解析之前处理。
2. `/start`、`/finish`、`/cancel` 保留 64 KiB 控制请求上限。
3. `close_runtime()` 必须在任何超时提前返回之前执行 `chunked_uploads.close()`，清理未完成的 `.part` 文件。
4. 保留兼容端点 `POST /api/import`。
5. 保留后端 `_POST_ROUTE_TABLE` 的 `/api/search` 分发，并确保上传控制路由不会被覆盖。
6. 数据迁移不得与正在上传、完成上传、配置写入或索引发布并发；最终合并分块上传时要接入同一维护/持久化边界。
7. 前端收到 413、416、503 时必须读取 JSON `error`（416 除外）并正常结束 loading 状态。
8. WindowsPDFViewer 的 `CancelledError` 必须继续原样上抛，关停时不得回退打开 Adobe/系统阅读器。
9. 合并后更新前端资源 SHA/字节数、0.4.0 发布说明及四个构建脚本的测试门禁。
10. 合并后至少运行：分块上传、请求上限、关停、Range、搜索 span/occurrence、WindowsPDFViewer 和完整非私有样本测试集。
