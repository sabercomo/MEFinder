# v0.5.0 MCP v1 只读工具契约

更新日期：2026-08-29

状态：0.5.0 冻结（契约身份仍为 `mefinder.mcp.v1`，向后兼容地新增工具）

机器可读契约：`docs/contracts/v0.5.0-mcp-v1-tools.json`

## 1. 范围

MCP v1 提供七个只读工具：

1. `list_documents`：筛选本地文献并取得稳定的 `source_file_id`；
2. `locate_quote`：定位原句并返回可核查证据；
3. `read_document_window`：从命中位置继续读取有界上下文；
4. `verify_quotes`：一次核对多条引文，为每条返回 `verified`/`approximate`/`not_found` 状态与候选原句（0.5.0 新增）；
5. `diff_quote`：把疑似抄错的引文与最接近的原句逐字符对齐，标注增/漏/改差异（0.5.0 新增）；
6. `search_passages`：按自然语言描述或关键词按相关性召回可能相关的原文段落，用于只记得大意时找回原文（0.5.0 新增）；
7. `read_bibliographic_pages`：返回文献前部与尾部的候选页面文本并标注书目线索，供调用方从原书自身提取题录（0.5.0 新增）。

`verify_quotes` 与 `diff_quote` 都建立在 `locate_quote` 的检索之上，只是把结果重组为批量核对报告和字符级差异，不引入新的检索或裁决逻辑。`search_passages` 是相关性检索而非逐字核对，命中不代表逐字一致，见 §4quater。`read_bibliographic_pages` 复用结构化阅读器的物理页读取，只多做书目线索标注。

v1 不包含导入、删除、页码校准、题录修改、备份恢复和数据迁移。工具不访问网络，不返回本地绝对路径，也不返回前端 HTML。

## 2. 权威定义

JSON 文件是工具名称、输入 schema、精简输出 schema、安全标注、错误码和初始化 instructions 的权威定义。本文件解释语义；两者冲突时，以 JSON 为准并修正文档。

机器可读文件在根级 `$defs` 复用公共类型；MCP `tools/list` 单独发送每个工具时，适配层必须把该工具实际引用的定义及其传递依赖附到对应 `outputSchema.$defs`，保证该 schema 脱离合同文件后仍可独立解析和校验，同时避免向模型重复发送无关定义。

所有成功结果都包含 `schema_version: "1"`。字段只能向后兼容地增加；删除字段或改变字段语义必须发布新的主 schema 版本。

七个工具统一声明：

```json
{
  "readOnlyHint": true,
  "destructiveHint": false,
  "openWorldHint": false
}
```

## 3. 页码语义

- `physical_page` 只表示 PDF 文件中的物理位置，索引从 0 开始；它不能自动作为正式引用页码。
- `citation_page` 只表示经 MEFinder 现有页码规则确认、可用于引文的页码。
- `citation_page.status=calibrated` 表示 PDF 引用页码已经校准或验证。
- `citation_page.status=verified` 表示 Word 页码已经验证。
- `citation_page.status=uncalibrated` 表示有物理 PDF 位置，但没有可安全引用的页码。
- `citation_page.status=unavailable` 表示当前记录没有可用页码位置。

适配层必须读取现有结构化字段作出上述转换，禁止解析 `page_display` 中文字符串反推状态。

## 4. 搜索证据语义

`locate_quote` 返回的是候选证据，不返回“文献已核实”之类的最终裁决：

- `paragraph_id` 标识一次真实出现位置；相同文字出现在多个段落时不得再次按文本去重。
- `match_type` 和 `match_score` 说明检索方式及排序证据，不等价于题录或引文结论已经确认。
- `context_before`、`context_after` 只返回现有搜索引擎提供的相邻正文。
- `reader` 给出继续调用 `read_document_window` 的自然位置。
- 输出禁止包含 `highlighted_html`、`copy_text`、绝对路径和内部调试证据。

无结果是成功响应：`total=0`、`matches=[]`。它不能转换成故障，也不能伪造候选。

## 4bis. 批量核对与错引比对语义

`verify_quotes` 对每条引文复用 `locate_quote` 的检索（默认 `mode=auto`），并按最佳候选给出状态：

- `verified`：最佳候选为精确族匹配（`match_type` 非 `fuzzy`）或 `match_score` 达到 1.0，即引文逐字出现在索引中。
- `approximate`：只存在模糊候选，引文疑似抄错，应转 `diff_quote` 复核。
- `not_found`：没有任何候选（`total=0`、`matches=[]`）。

`verify_quotes` 只统计与转发候选，不改写引文，也不把 `approximate` 升级为“已核实”。

`diff_quote` 只在最佳候选的 `matched_text`（原文切片）与用户引文之间做字符级对齐（默认 `mode=fuzzy` 以便召回疑似原句）：

- `diff` 分段的 `op` 取值：`equal`（一致）、`added`（引文多出、原文没有）、`missing`（原文有、引文漏掉）、`changed`（同位置不同）。偏移量按 Unicode code point 计。
- `status=identical` 表示引文与原句完全一致（`stats` 各差异计数为 0）；`different` 表示存在差异；`not_found` 表示索引中没有可比对原句，此时 `match`、`similarity`、`stats` 为 `null`，`diff=[]`。
- `similarity` 为引文与原句的 `SequenceMatcher` 比率，仅作参考，不替调用方裁决对错。

## 4ter. 版权页提取语义

`read_bibliographic_pages` 为"从原书自身补全题录"提供原料，不联网、不改写、不裁决：

- 版权页与图书在版编目（CIP）页可能出现在书首或书尾，因此工具同时返回 `front`（从 0 开始）与 `back`（末尾若干页）两组候选；文档过短导致两端重叠时，尾部去除已在 `front` 中出现的页，二者位置不相交。
- 每页给出既有解析文本 `text`、`position`、`physical_page` 与 `citation_page`，`item_type` 表明单位是 PDF 物理页还是 Word 段落。工具只读取结构化阅读器已保留的物理页文本，不做正文过滤。
- `hints` 标注该页命中的书目线索（`isbn`、`cip`、`publisher`、`price`、`responsibility`、`year`），`likely_copyright_page` 在出现 ISBN/CIP 或命中三条以上线索时为真。线索只是提示，调用方仍须据 `text` 自行提取。
- 提取到的题录必须来自返回的页面文本本身；工具不生成、不回填、不校验题录，写回题录属于 v1 范围之外。

## 4quater. 相关性检索语义

`search_passages` 是**检索而非生成、更非逐字核对**：它按自然语言描述或关键词，返回可能相关的原文段落，供“只记得大意、无法逐字引用”时找回原文。

- 与 `locate_quote`/`verify_quotes` 的根本区别：后者要求查询近似原文子串并判定逐字是否一致；`search_passages` 只按相关性排序，**命中只表示该段与描述相关，绝不代表逐字一致**，因此 `passage` 不含 `match_type`/`match_score`。要逐字定位或核对，须改用 `locate_quote`/`verify_quotes`。
- 每个 `passage` 给出整段 `paragraph_text`、预览片段 `preview`、上下文、页码证据（`physical_page`/`citation_page`/`page_mapping`）、可复制引用 `citation`（中文与 GB 格式串及其完整度状态）以及 `reader` 游标，字段与检索工具保持同源，便于据此转 `locate_quote` 逐字核验。
- `relevance` 给出 `rank`（从 1 起的名次，取用以此为准）、`method`（当前为 `bm25`；无 FTS 时回退 `trigram`）与 `score`。**`score` 仅是本次返回结果内部的相对相关度（1 最相关），不可跨查询比较。**
- 召回按候选预算截断，`total` 为候选数、`total_is_exact` 在截断时为假，与 `locate_quote` 同义。
- 检索层被隔离在 `SearchEngine._retrieve_passages` 后：将来以向量嵌入替换该方法即可升级召回质量，`passage` 契约与工具形状不变。当前实现只复用既有的 SQLite FTS5 trigram（`bm25`）索引，不引入任何新的离线或联网依赖。

## 5. 错误语义

边界只转换已知错误；未知异常记录到 STDERR 后按 `internal_error` 失败，不伪装成“未找到”。

失败调用返回 `isError=true`；其 `structuredContent` 按机器合同中的 `errorSchema` 返回，文本 `content` 只保留同一错误对象的紧凑 JSON，不包含本地路径、堆栈或原始异常消息。

| 错误码 | 场景 | 可重试 |
| --- | --- | --- |
| `invalid_input` | 参数不符合 schema | 否 |
| `index_not_found` | 当前数据根没有索引 | 否 |
| `index_unavailable` | 索引正在替换、锁定或暂时不可读 | 是 |
| `source_not_found` | 文献 ID 不存在 | 否 |
| `unsupported_source_type` | 文献类型不支持结构化阅读 | 否 |
| `internal_error` | 未归类故障 | 否 |

## 6. 本阶段验证边界

0.4.4 第一阶段只验证契约与既有业务基线，不实现 MCP Server。公共合成夹具必须覆盖：

- PDF 已校准引用页；
- PDF 只有物理页、引用页未校准；
- Word 文献；
- 精确搜索结果与阅读窗口；
- 无搜索结果。

后续服务层和 MCP 协议层必须复用同一夹具，不依赖用户个人文献库。
