# v0.5.9 译本对齐任务进度

2026-10-10：开发源码支持真实阶段进度与当前阶段预计剩余时间，沿用现有成功、失败、取消响应。

`GET /api/text-alignments/status?job_id=...` 的 HTTP 202 响应新增 `progress`；`GET /api/text-alignments/current` 在 `running: true` 时提供相同快照，刷新页面可恢复显示。

```json
{
  "job_id": "...",
  "status": "running",
  "progress": {
    "stage": "embedding",
    "completed": 64,
    "total": 200,
    "percent": 32,
    "eta_seconds": 120.0
  }
}
```

- 阶段依次为 `preparing`（准备文本）、`loading`（加载模型）、`embedding`（文本计算）、`matching`（段落匹配）、`checking`（检查对应关系）、`saving`（保存结果）。缓存完整命中时跳过文本计算。
- 文本计算按实际待计算的去重文本计数，不把已缓存的段落当作待计算文本；段落匹配按正文源段落的处理位置计数。`percent` 为当前阶段百分比，阶段切换后重新计数，不是全任务耗时占比。
- `eta_seconds` 为当前阶段已处理数量与实际耗时的平均速度估算，不含后续阶段；尚无有效速度样本时为 `null`。准备、加载、检查、保存阶段没有可测分母，`percent` 和 `eta_seconds` 为 `null`。
- 计算 worker 通过原有 NDJSON `progress` 消息提供 `stage`、`completed`、`total`；不改变计算请求、结果身份、算法版本及数据库 schema。主进程计算估时，前端每 1.5 秒读取并局部更新。取消、失败及成功终态均清除在途进度。
