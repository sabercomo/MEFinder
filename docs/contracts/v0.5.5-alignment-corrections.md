# v0.5.5 人工校正的读取口径

2026-09-20：统一人工校正（`alignment_manual_overrides`）的读取规则与「待检查」判定。路由不变，`GET /api/text-alignments/links` 的每条链接新增一个字段。

## 单一读取路径

`text_alignment.confirmed_overrides_for_pair()` 是三个消费方（`locate_alignment`、`alignment_link_window`、作品页逐对统计）唯一的读取入口，`override_for_selection()` 是唯一的选取规则：

| 规则 | 说明 |
|---|---|
| 有效性 | 只返回 `status='confirmed'` 且 `target_segment_set_id` 等于当前对齐目标分段集、目标段在该分段集中全部存在的校正。重新对齐或重新分段之后遗留的校正一律视为过期，**不映射到当前对齐不再使用的段**。 |
| 精确优先 | 选区的 segment key 完全命中时用该条校正。 |
| 包含回退 | 没有精确命中时，只有 `evidence.origin = "reader_review"` 的校正可以作用于它所**包含**的选区（阅读器校正描述整条链接，滚动定位命中的往往只是其中一段）；范围更小者优先，同范围取确认时间更晚者。MCP 提案仍是精确选区语义。 |

此前三处各写一份：定位有「包含回退 + 过期判定」，链接窗口只有精确命中，逐对统计既无过期判定也无有效性校验（陈旧校正仍被算作已处理）。

## 「待检查」的唯一判定

一条链接需要人工检查，当且仅当：`review_status = 'rejected'`（算法给出对应但低于置信门槛）**且两侧都非空**（一侧为空是「没有对应」，副文本或漏段，不计）**且两个方向都没有有效校正**（读者从哪一版改都算改过）。

- `GET /api/text-alignments/links` 的每条链接新增 `needs_review`（布尔），由后端按上述规则判定；阅读器的「!」标记直接读它，不再自行按 `review_status` / `manual` 推算。
- `GET /api/translation-works/overview` 的 `review_count` 是同一规则在整个 run 上的计数，两个数字口径一致。
- `manual`（`corrected` / `no_counterpart` / null）与 `deferred` 字段含义不变；`manual` 现在也遵循上面的包含回退，与定位结果一致。

守卫：`tests/test_translation_works.py` 的 `test_correction_settles_link_for_locate_window_and_count`、`test_correction_from_the_other_side_settles_the_same_link`、`test_correction_left_behind_by_resegmentation_is_stale_everywhere`；前端口径由 `tests/test_structured_reader_frontend.py` 钉死。
