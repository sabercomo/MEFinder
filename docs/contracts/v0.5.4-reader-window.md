# 0.5.4 独立阅读窗口契约

2026-09-10：开发分支新增可选原生阅读窗口，默认关闭；安装包尚未发布。

## 偏好

`GET /api/preferences` 与 `POST /api/preferences` 增加 `reader_window_enabled`。
该值仅接受 JSON 布尔值，默认 `false`。历史偏好缺少该字段或磁盘数据类型无效时按关闭读取；
POST 非布尔值返回 400。局部更新其他偏好必须保留该值，随现有偏好文件备份和迁移。

开关位于桌面设置 → PDF 阅读，下一次打开结构化阅读时生效。
关闭后保持现有弹层；开启后 macOS / Windows 桌面入口创建独立窗口。
浏览器运行方式保持原有弹层，不依赖 pywebview；PDFKit／系统 PDF 打开偏好独立保留。
已打开窗口不因切换开关而被关闭或迁移。

## 阅读器与宿主

`MEFinderReader.configure` 增加可选的 `openExternal(options)` 和 `onClose()` 回调。
`openExternal` 返回真值代表宿主已接管打开；此时主页面不创建阅读 DOM、不改变阅读位置。
关闭回调在阅读状态和请求清理之后执行，独立窗口使用它关闭自身。

主窗口通过 pywebview 暴露 `open_reader(options)`；位置是已有阅读器使用的 JSON 对象。
来源标识必须为非空字符串且不超过 256 字符；不得接收任意页面 URL。
文献 id、段落／PDF 锚点、字符区间、文本哈希与原句原样传递，不转换 Unicode code point 偏移。
该桥不负责检索、对齐或写库。

独立窗口只暴露自己的 `reader_options()`，用同一后台地址加载
`GET /reader-window`。HEAD 返回与 GET 相同的 Content-Length，返回空正文。
该页面只初始化阅读器、外观和提示，不初始化主搜索页、文献库或设置页面。
阅读深链接保留在 `/reader-window` 路径，重新加载仍保留阅读锚点；已有 `/reader` 链接兼容。

## 窗口生命周期

每次明确打开创建一个窗口，每个 WebView 各自持有阅读／对照状态。
共享本地 HTTP 后台及现有数据库接口，不复制正式数据库、不新建第二套索引运行时。
系统标题栏负责拖动、缩放、最小化和最大化，正文开启原生文本选择。
关闭阅读器仅销毁该窗口；主窗口实际关闭后关闭所有阅读窗口，随后沿用应用后台收尾。
开始退出后拒绝新的窗口请求；窗口创建失败向调用者传播，不静默改回弹层。

阅读器完成请求和状态清理后设置 `pywebview.state.readerClosed = true`。
宿主订阅该窗口的状态变更，仅在 `change / readerClosed / true` 时销毁窗口。
这是无需向页面回传结果的单向关闭通知，不暴露会先销毁自身、再等待 JS 回执的关闭 API。
不依赖固定延迟销毁，也不强制结束进程；后台沿用持久写入等待与正常释放流程。

外观和正文排版在打开及窗口重新获得焦点时读取现有偏好；跟随系统深浅色沿用主题引擎。

## 验证依据

- `tests/test_reader_windows.py`：默认值、持久化、输入校验、原样锚点传递、多窗口生命周期和创建失败。
- `tests/test_reader_windows_frontend.py`：执行真实 JS，覆盖默认弹层、保存失败、重复提交、搜索位置传递及浏览器兼容。
- `tests/test_structured_reader_web.py`：真实 SQLite/HTTP 偏好读写及独立页面 GET/HEAD。
- `tests/test_preferences_concurrency.py`：新偏好参与实际并发更新，无字段丢失。
- `tests/test_reader_windows_native.py`：显式启用时以隐藏原生窗口和临时数据库验证真实页面、窗口关闭及整个子进程自然退出；父进程超时负责诊断测试清理。

本契约不引入对齐运行库按需安装、跨窗口滚动联动或算法门槛变化。
