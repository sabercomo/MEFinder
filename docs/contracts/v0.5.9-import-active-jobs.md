# v0.5.9 重复导入与取消状态

`POST /api/import` 与 `POST /api/import-upload/finish` 对内容相同的 PDF 复用正在运行或正在停止的导入任务。按完整文件 SHA-256 识别相同 PDF，并沿用文献库中已有的历史 source ID；不按文件名匹配。

重复提交返回 HTTP 200，保留既有成功字段，并增加：

| 字段 | 类型 | 含义 |
|---|---|---|
| `already_running` | boolean | `true` 表示复用已有任务，不提交新解析 |
| `status` | string | 原任务的 `processing` 或 `cancelling` 状态 |

`job_id`、`source_file_id`、`detected_pdf_type`、`parse_route`、`provider_id` 均取自原任务；新请求选择的解析方式不会覆盖正在运行的方式。页面合并同一 `job_id` 的重复队列行，继续通过 `/api/import-status` 跟踪。

`POST /api/import-resume-dismiss` 返回 `state: cancelling` 后，页面保留任务并显示“正在停止后台解析”，禁用重复取消。后台清理完成后，`/api/import-status` 返回 HTTP 404，页面才移除该行。普通任务的 404 仍按错误显示；取消清理失败仍显示后端失败信息。停止完成后重新导入可以创建新任务。

批量本地扫描保持既有冲突错误处理。数据格式、页码、数据库与 MCP 契约不变。
