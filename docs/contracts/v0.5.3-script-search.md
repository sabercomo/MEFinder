# v0.5.3 繁简统一检索契约

2026-09-08：PR #21 的 Web/桌面全文检索契约；开发代码可测试，尚未发布安装包。

## 行为与边界

只转换查询关键词，原文不转换、不重建索引。用简体关键词可命中 OpenCC 对应的繁体原文，反向亦然。结果段落、引文、字符区间、PDF 页码及 MD/EPUB 导出仍取原始内容。通用 t2s/s2t 不保证地区同义词、任意繁简混写或所有一对多异体字全部命中（例如軟體→软体，不是软件）。

## 偏好 API

- `GET /api/preferences` 增加 `script_folding: bool`，缺省为 true；增加只读能力字段 `script_folding_available: bool`，须两套转换器及词典均可加载。
- `POST /api/preferences` 接受严格布尔值 `script_folding`。非布尔值返回 400；部分更新保留其他偏好；成功沿用 `{ok: true, ...preferences}` 返回格式。
- `POST /api/search` 请求形状保持原有契约，设置即时影响下一次请求。关闭、OpenCC 缺失或查询没有变体时直接调用原搜索。
- 设置加载前及组件不可用时开关禁用；保存期间禁用，失败恢复之前值并提示。

## 搜索合并

`auto` 依次经过 exact、compact、punctuation、fuzzy；每个阶段先尝试全部查询变体，任一命中或候选截断即停止降级。显式模式原样执行。按匹配分数降序，原始查询作为同分优先级，保留各分支原有顺序。

按 source_file_id、paragraph_id、match_start、match_end 去重。保留同一段落中不同字符区间的命中，返回偏移始终对应原文。

限额与现有引擎一致：普通限额夹到 1–200；`all` 与字符串 `0` 不设返回限额。HTTP 数字 0 由 DTO 转为 `all`；直接构造 DTO 的整数 0/None 沿用引擎缺省 10。

只有所有变体都提供完整、精确结果时，联合 total 才精确。否则 total 为已知去重数量与各分支 total 的最大值（下界），`total_is_exact=false`、`has_more=true`，不相加夸大数量。完整联合仍因最终 limit 裁剪时 total 精确、has_more 为 true。

## 适用范围与发布条件

接线在 Web/桌面 IndexRuntime；独立 IndexRuntime 可注入偏好，默认沿用旧搜索。MCP 和文本对齐没有接入该偏好。新依赖固定 `opencc-python-reimplemented==0.1.7`，桌面打包须包含配置与词典。源码回归、词典收集检查不能替代 Windows/macOS 成品构建和真实大库性能验证。
