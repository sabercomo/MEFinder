## 前端必须保留

- 使用 `/api/import-upload/start → chunk → finish` 上传文件；失败或用户取消时调用 `/cancel`。
- 默认使用后端返回的 `chunk_size`；前端自身仍限制最大分块为 8 MiB。
- 每块以服务端 `received_size` 作为下一块 offset，不允许跳块。
- `/finish` 成功响应继续按旧导入响应读取：`job_id`、`source_file_id`、`detected_pdf_type`、`parse_route`、`provider_id`。
- 支持普通 JSON 请求的 413 和应用关停 503，失败时清除 loading/processing 状态。
- 搜索高亮使用 `[match_start, match_end)`；不得自行对 normalized text 的位置重新映射。
- 同一句文字可以在不同 `paragraph_id` 返回多条；前端不得再次按文本去重。
- `page_match_spans` 可能包含两个物理页，这是有效的真实跨页命中。
- 导入任务按 `phase="queue_failed"`、`failure_stage="queue"`、`can_resume=true` 展示可继续状态，不要解析中文 `message`。

## 最终合并时必须共同确认

- 分块 raw body 路由在 1 MiB JSON gate 之前。
- 上传 staging 在所有关停返回路径上被清理。
- 分块完成与数据迁移不能并发。
- 兼容 `/api/import` 暂不删除。
- 前端纯逻辑测试、分块上传测试及后端完整回归全部通过后，才能标记 0.4.0。
