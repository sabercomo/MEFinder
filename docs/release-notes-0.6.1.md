# MEFinder 0.6.1（开发中）

## 开发维护

- 修正 SQL 架构检查误报：按文件与完整调用目标排除已核实的搜索服务、解析执行器调用，不再把四个应用服务模块计为数据库查询模块。
- 将 persistence 之外的 SQL 棘轮从文件集合改为逐文件调用数量；已有模块增加 SQL 与新增 SQL 模块均会触发门禁。首次校准为 10 个文件、72 处调用，后续搜索查询迁移后收紧为 8 个文件、68 处，含解析任务账本的 schema 与事务语句。
- 新增隔离源码树回归测试，覆盖服务与 SQL 混合调用、动态查询、游标、批量执行、未知执行器以及现有模块内增加调用等情况。
- 运行时版本、MCP 契约 release、HTTP 契约快照、Windows 冒烟工作流和相关测试同步到 0.6.1；HTTP 路由与 MCP 工具接口未变。版本展示使前端装配摘要变化，字节数保持不变。
- 搜索精确/标准化、忽略空格/标点的候选查询与上下文查询统一归入持久化层，保留原连接、流式读取、候选预算和查询计划；评分、页码和字符定位规则保持不变。
- PDF 提取拆分为导入协调、原生解析、段落及锚点构造三项职责；保留旧导入入口，新增完整输出快照和单向依赖守卫。
- 新增 `errors.UserFacingError` 表示“消息可直接给用户看的预期错误”，`MinerUError` 改为它的子类。备份、删除、导入任务、页码映射、各 controller、CLI 与 web 装配等 21 个与 MinerU 无关的文件不再借用 `MinerUError`；仍导入它的只剩 5 个 MinerU 解析相关文件，并由守卫钉住。捕获范围与 HTTP 状态码、错误文案保持不变。
- 跨模块共用的 96 个私有辅助函数/常量/类改为公开名（另 2 个本已公开、只是被私有别名转手），使用方一律从定义模块直接导入，不再经 `text_alignment`、`database` 等旧模块转手；跨模块私有导入从 152 处降为 0，并新增守卫禁止回潮。只改名称与导入路径，函数逻辑未改。

## 范围与限制

本轮完成架构评估的三项局部整理，以及 2026-10-31 评估的第 1、2 项（通用错误、私有辅助函数），不调整检索算法、页码策略或 schema，也不重解析用户文献库。唯一可观察差异：导入索引失败、文档包导入失败、PDF 页内文字刷新失败这 3 处提示会带上异常类名；若失败原因是已迁移的通用错误，类名由 `MinerUError` 变为 `UserFacingError`。静态检查采用已核实目标的精确豁免，不做 Python 类型推断；未知的 `execute*` 调用仍计入棘轮，需审阅后确认归属。

既有 0.6.0 发布说明和安装包保持不变；0.6.1 尚未打包、安装或发布。
