# 正文范围检查与修改

记录「正文范围」检查/修正入口的产品决定、接口契约与验收证据。自动识别本身的修复见
[alignment-body-range-collapse.md](alignment-body-range-collapse.md)。

## 2026-09-20：入口落地（事实）

### 为什么需要它

对齐路线第 1 步是修前处理：正文范围识别错了，后面的算法再好也对不齐。自动识别已修掉
一类塌缩（编者导论的参考文献表被当成全书书末），但**识别错时用户没有任何地方能看见和
改正**——这是本次补上的部分。后端早已具备每本书一个连续范围的能力
（`generate_alignment(reviewed_body_ranges=...)` 与「同一分段上自动复用最近一次人工范围」），
缺的是 HTTP 接口与界面。

### 产品决定（用户确认，优先于原型）

- 从作品页**具体版本对**的「正文范围」入口打开，两本书并排，各自独立浏览与修改。
- **删除单本确认环节**：原型里的「确认这本的范围 / 已确认这本的范围」按钮与
  「范围待确认 / 范围已确认」状态全部不做。底部只有一组提交：「取消」与
  「保存范围并重新对齐」。两个范围有效即可提交，不要求用户改过两本、不要求重复点击
  原本就正确的起止，提交后不再加核对页或确认弹窗。
- 点选文本段只改变**当前选中段**，只有「设为开头 / 设为结尾」才改范围；开头与结尾始终
  可见，可「查看」跳回原文，可「撤销」本次修改。
- 首尾均包含、中间连续纳入。不做逐段排除、多段范围、分节类型编辑或段落配对。
- 结尾早于开头时就近报错并禁止提交，不自动移动另一端。

### 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/text-alignments/body-range` | 入参 `document_group_id` / `pivot_source_file_id` / `target_source_file_id`；返回两侧的 `segment_set_id`、`segment_count`、`body_start_index`、`body_end_index`（**界面口径：含最后一段**）、`outline`、首尾段落及其页码锚点，顶层 `range_source` 为 `reviewed` 或 `detected`。用 POST 是因为从未对齐过的一对会在这里首次分段落库（只分段，不对齐、不重解析源文件）。 |
| GET | `/api/text-alignments/body-range/segments` | `source_id` + `segment_set_id`（+ `start` / `count` / `pdf_page`），返回一窗文本段及其既有页码锚点。只读，不创建分段；`segment_set_id` 与文献不匹配即 400。 |
| POST | `/api/text-alignments/start` | 新增可选 `reviewed_body_ranges: {pivot: [start, end), target: [start, end)}`，随该次运行写入 `parameters_json`（`body_range_source=reviewed`）。 |

界面显示的结尾是最后一段，提交时 `+1` 换算成库内半开区间——**这是最容易漏末段的一处**，
前端 `test_translation_works_frontend` 与后端 `test_alignment_body_range` 两侧都钉住了。

### 边界与已知限制（如实记录）

- 范围按**文本段序号**记录，绑定这两本书当前的分段集。重新解析产生新分段集后，旧的人工
  范围不再匹配（`latest_reviewed_body_ranges` 按 `pivot_segment_set_id` + `target_segment_set_id`
  查），界面不承诺跨重新解析永久有效。
- 页码只来自既有锚点，经 `page_display.build_page_display` 生成，与检索/阅读同一套口径：
  PDF 显示「引用页码：N」或「PDF 第 N 页，引用页码尚未校准」，无出版方页码的 EPUB 显示
  「页码尚未解析」。两本书的页码互不对应，不按页码相等建立关系。
- **按页跳转目前只对 PDF 提供**。带出版方 page-list 的 EPUB 虽有可信页码（逐段显示无误），
  但把用户输入的数字匹配回 `page_display` 存在罗马数字与「Page 93.」这类写法的歧义，宁可
  不做也不猜，EPUB / Word 用目录章节与文本段序号定位。若将来要做，需要先有明确的
  出版方页码索引，而不是字符串匹配。（推断：此限制不影响正文范围的准确性，只影响定位便利。）
- 目录来自 `_document_heading_positions`（与范围检测同一套标题识别），标题取该文本段自己的
  首行，不生成标签；目录页里的同名行不会混进来。
- 提交会**强制重跑当前版本对**（`force: true`），不影响同一作品里的其他版本对。

### 验收（本机真实副本，2026-09-20）

- 全量 `unittest` 2442 项通过（23 跳过）；Ruff（src / tests / scripts）零告警；前端装配指纹与
  HTTP 契约 JSON 已同步。
- 浏览器验证在 `.codex-tmp/gender-alignment/index.sqlite3` 的**副本**上进行（《谁在害怕性别》，
  中文 EPUB / 英文 EPUB / 中文 PDF 三个版本），未触碰任何原始库：
  - 英文 EPUB 5532 段、中文 EPUB 3951 段，自动识别范围、真实章节目录、出版方页码
    （`第 Page v. 页`）与 PDF 引用页码（`引用页码：114`）均按实际数据显示。
  - 左右独立：改左侧结尾后右侧范围与视图不变；非法范围就近报错且禁用提交；撤销逐步回到
    自动识别范围并自行变灰。
  - 「查看」跳到第 4231 段（书末 Notes），目录跳到第 3 章，PDF 按页跳转到第 120 页
    （显示引用页码 114），不存在的页码只报「这一页没有可选文本，请换一页」且视图不变。
  - 提交：以左侧收窄到「文本段 26」为例，`/api/text-alignments/start` 实际收到
    `reviewed_body_ranges {pivot: [22, 26], target: [3, 3918]}` + `force: true`——首尾包含关系
    正确，未修改的一本沿用当前显示范围。**该次提交的请求被拦截，未真的跑模型**（本机预览
    运行时未装对齐模型组件）；真实计算闭环仍待用户在装有组件的环境里验收。
  - 失败后草稿保留：模拟任务失败后重开弹窗，显示「已恢复上次未成功提交的范围」并恢复两侧
    选择，可直接重试。
  - 主题与窄窗口：浅色与深色主题下选中态、边界与说明文字可读；760 px 宽时两栏叠为上下，无
    横向滚动。键盘：Escape 关闭，焦点在设完某端后留在同一本书当前选中的文本段。
- **未验证**：真实模型下的完整「提交 → 重算 → 结果变化」闭环；Windows / WebView2 布局。

## 2026-09-20：复审修正（事实）

复审发现，上述“左右视图不变”结论未覆盖目录展开、输入框未提交值和滚动位置；
“绑定当前分段”也只覆盖已保存范围的复用，没有覆盖编辑期间重新解析的情况。

- **旧段号误用于新文本**：从编辑到提交之间更新解析文本，原起点“第一章 商品”对应的段号
  变为“新增前置材料”后仍被接受。现提交同时携带两侧 `expected_segment_set_ids`，在准备对齐的
  写事务中比较；任意一侧变化即拒绝，不进入计算、不写新的运行。HTTP 字段成对约束见
  [v0.5.5 正文范围契约](../contracts/v0.5.5-body-ranges.md)。
- **整窗重绘打断浏览**：单侧操作以前会重建整个弹窗。现只更新对应书的摘要、文本与操作状态，
  保留目录、输入框与滚动容器节点；选段/设置/撤销保留原滚动位置，主动跳转或翻页才回到新文本窗口顶部。
- **摘要与按钮无法同时看到**：改为每本书正文单独滚动，书名、起止摘要、导航与设置按钮在正文区之外。
  窄窗口上下排列，两本书各占可用编辑区高度，避免底部提交区遮挡设置按钮。

### 回归证据与复跑

- 本轮全量 `unittest` **2450 项通过（23 跳过）**，前端装配指纹同步；Git 跟踪的 Python 文件
  Ruff 检查通过，Node 语法与 `git diff --check` 通过。`ruff check .` 扫到既有未跟踪
  `.codex-tmp/` 实验目录的 21 条告警，本轮没有修改或清理这些文件。
- `test_reparsed_text_rejects_old_ranges_before_computation_or_writes`：真实修改 fixture 中已入库的解析文本，
  旧范围被拒绝，嵌入函数未调用，`alignment_runs` 为零。
- `test_matching_segment_sets_accept_both_ranges_and_reuse_them`：匹配的两侧分段集可保存范围；
  后续普通重跑继续复用。该测试使用合成嵌入，不作为真实模型质量证据。
- 控制器拒绝缺失/错误版本标识；协调器测试覆盖范围与版本标识的透传。
- 新增 `scripts/check_body_range_ui.cjs`，以真实书库副本的 HTTP 服务进行浏览器回归：
  左侧选段不改变右侧目录、输入或滚动；设置与撤销不跳动；非法范围禁用提交；取消丢弃未提交修改；
  请求携带两个范围与两个版本标识；模拟提交失败后恢复草稿；1280 / 768 / 414 / 375 / 320 px
  均无横向溢出，起止与设置按钮不被提交区遮挡，窄窗口第二本书同样可操作。
