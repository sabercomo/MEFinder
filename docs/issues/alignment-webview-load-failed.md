# 作品组长对齐请求出现 Load failed

## 2026-09-09 — 事实

- 用户报告 MiniLM、E5 对 EPUB 与 PDF／MinerU JSON 生成对齐时显示 `Load failed`。
- 桌面日志记录 17:57:31 开始 PDF→英文 EPUB，18:01:37 完成并保存 1,732 组可定位链接；
  中间 17:58:58、18:01:28 又收到相同请求。说明界面失败不等于模型计算失败。
- 同机 pywebview / WKWebView 对本地延迟 70 秒的 HTTP 响应，在 61.006 秒抛出
  `Load failed`。复现完全不涉及 PDF、JSON、模型或生产库写入。
- EPUB 旧对齐仍保存中文 `[539,3918)`／英文 `[500,4231)`，截图选句在中文 order 41。
  当前正文检测已改为 `[3,3918)`／`[22,4231)`，但已保存结果不会自动更新。
- 详细验证与结果见 `reports/gender-alignment-recovery-2026-09-09.md`。

## 推断与修复

- 推断：本次管理作品组失败由浏览器长请求超时触发；实际模型任务继续运行，重复点击产生排队，
  关闭软件又取消未完成任务，使用户持续看不到成功结果。
- 前端改为后台启动、短请求轮询；同一任务去重，不同任务明确报忙。后台终态错误和取消透传，
  不将异常吞掉或伪报成功。既有同步 API 保留。
- 区域版本升到 2，防止生成操作复用旧正文范围。阅读旧结果时，只在选区被旧自动范围排除、
  当前检测确认属于正文时提示重新生成；人工复核范围仍为权威，未放宽置信度或副文本门禁。
