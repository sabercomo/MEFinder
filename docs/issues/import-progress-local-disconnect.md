# 本机进度查询断连后导入队列误报失败

## 2026-10-15 — 现场与原因

**事实**：用户截图中，`me2-38.pdf`、`me2-40a.pdf`、`me2-42.pdf`、`me2-43.pdf`、`me2-44.pdf` 在“本地解析”阶段显示 `Failed to fetch`。本机日志记录五份文件均已完成传入、识别为 `native_text` 并提交后台任务；只读状态接口返回 `me2-40a.pdf` 与 `me2-42.pdf` 已完成，其余三份仍在等待处理。后台任务继续推进，截图不代表解析失败。证据与验证见 [核验报告](../../reports/import-progress-reconnect-2026-10-15.md)。

**事实**：`80-import.js` 的 `pollImportJob` 把查询请求的所有异常都写为 `q.status = 'error'`，且没有再安排查询。前端因此失去与后台任务的状态同步。这里的请求是页面访问同机 `127.0.0.1` 的 HTTP 接口；这批原生文本 PDF 走本地处理，不涉及互联网解析。

**待核实**：现有日志没有记录现场请求中断的底层原因，不能据此断言是服务崩溃、资源耗尽或 PDF 损坏。

## 2026-10-15 — 修复与边界

仅在读取状态的本机通信边界捕获 `TypeError`（包括请求失败与响应正文读取中断）：保留原任务状态、步骤、解析方式与取消标记，显示本机连接中断及重试提示，沿用 2.5 秒间隔重新查询；原始异常写入控制台。恢复后由后台返回的进度与终态更新界面。

取消中的任务仍显示“正在停止”，取得 404 后移除。普通 404、无效 JSON 和后台明确返回的导入失败保持错误展示与原有恢复入口，不当作断连自动重试。任务移除后，不再继续发出状态查询。

本轮只修复进度查询；保留现有原生 JS 界面，未迁移 Vue，未改上传、解析、索引或数据库流程。

## 2026-10-20 — 合并 macOS 导入状态整理

**事实**：远端断连恢复修复基于旧的 `80-import.js` 轮询，本地已将任务所有权移至 `78-import-jobs.js`。合并时将相同的通信边界处理迁入任务模块；重试前与定时器触发时均核对当前监听，继续保留单任务单轮询链。普通错误、无效 JSON 和真实导入失败仍终止轮询。

**事实**：将远端断连、正文中断、取消恢复及删除后停止查询的用例改为执行完整任务模块，四个断连场景先失败、修复后通过；原有旧响应隔离与单轮询用例保留。浏览器断连场景通过公开任务入口构造，避免访问已封装的内部队列。完整构建与交付证据见 [macOS 双架构核验报告](../../reports/macos-release-2026-10-20.md)。
