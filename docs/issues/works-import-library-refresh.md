# 导入完成后译本对照页沿用旧文献目录

2026-10-10：刷新遗漏已修复，全量门禁通过；原 `dist/MEFinder/` 的外置资源已同步，重启程序即可生效，尚未正式发布。

## 事实与原因

用户截图中，文献库显示《当代资本主义批判》的语言为“简体中文”，译本对照页却显示“语言未识别”；同一版本的副标题退化成 `pdf-import-735d8e37b120ae45`，出版与页码信息也为空。

`35-works.js` 的 `works.catalog` 保留已加载的文献目录。`80-import.js` 的 `pollImportJob` 在导入完成时只调用 `invalidateLibraryCatalog()`，刷新搜索和文献库共享目录，没有失效译本对照页的 `works.loaded`。下一次打开作品时，`load()` 直接复用旧目录，`sourceById()` 查不到新导入的文献，语言、书名、格式、出版和页码信息一并缺失。

只读核验真实数据库：该来源与作品组关联均存在；本轮查询时已有分段记录的语言为 `zh-Hans`。这说明当前数据存在，不能把截图中的“未识别”解释为当前中文检测失败。

## 修改

在导入完成分支中，失效共享目录后调用现有 `MEFinder.works.invalidate()` 和 `load()`。无论对照页是否可见都立即重新加载，保留文献库“加入作品”入口；当前对照页可见时同步刷新版本信息。沿用共享请求去重，不重新解析、不生成对齐、不修改数据库、语言检测或页码策略。

## 验证

新增 `test_completed_import_refreshes_version_metadata_on_visible_and_hidden_works`，直接执行现有导入轮询、目录请求和作品加载函数。旧代码首先因隐藏作品页未失效而失败，补一行通知后通过。

覆盖导入完成时停留在导入页、文献库页、译本对照页三个场景；验证新版本的中文语言、书名、出版信息、PDF 格式与页码来源恢复，并且只发起一次共享目录请求。失败导入不失效目录、不额外请求。
