# 默认启动时文献摘要被对齐总览排队

2026-10-17：已修复默认搜索页跳过摘要等待的启动时序；门禁通过，原 `dist/MEFinder/` 外置资源已同步，下次启动生效。测量与验证见 [核验报告](../../reports/library-startup-2026-10-17.md)。

## 事实

- 默认首页是搜索页，初始化时 `searchStore.libraryCatalogPromise` 尚为空。原 `90-init.js` 回退到已完成的 `Promise.resolve()`，因此没有真正等待文献摘要。
- 浏览器空闲预取的 `works.load()` 同时发出对齐总览与摘要；总览经 `IndexRuntime.run_when_ready` 持有索引锁。原代码的 Chrome 复现观察到 `overview → summary`，新增 Node 行为测试与 Chrome 测试均在修复前失败。
- 使用现有 468 篇书库只读数据、相同索引锁规则，清空进程内正文范围缓存后，总览先行时摘要耗时 4.08–4.75 秒；摘要先行时为 0.71–0.72 秒。已有正文范围缓存时原顺序约 0.70–0.73 秒，不能把缓存命中也说成显著提速。
- 今日桌面日志的索引加载至后端就绪约 156 毫秒；该时间不含后续接口和列表渲染。

## 推断与边界

该时序在对齐总览需要重新核对正文范围时会拖慢文献摘要；仅凭现有桌面日志无法确定用户这次感知等待的全部耗时构成。上述对照是隔离的请求排队测量，不是双击程序至列表显示的端到端计时，也没有清空系统文件缓存。

## 修改

没有在途摘要时直接发起共享摘要请求；已有请求时继续复用。摘要完成后启动 Zotero 界面状态观察和空闲对齐预取。摘要失败沿用原异常出口；检索、页码、数据库、HTTP 与 MCP 契约不变。

回归：`test_startup_waits_for_catalog_before_works_on_default_search_page`、`test_default_startup_finishes_catalog_before_alignment_overview`。

## 2026-11-22 — 启动时重复读取摘要

- **事实**：默认搜索页先读摘要，再启动 Zotero 状态观察。首次状态发现已有同步历史就刷新文献库，重新读取摘要，并使已发出的对齐总览失效。用 462 篇文献库的隔离副本复现，入口出现前最长的请求是文献摘要。见 [本次计时报告](../../reports/translation-work-startup-2026-11-22.md)。
- **修改**：默认启动先观察 Zotero 状态，再读取或复用共享摘要。首次观察时，若目录尚未开始请求，直接使用接下来的首次摘要。若已有目录或在途请求，继续刷新以覆盖真正的目录变化。对齐总览仍在摘要之后发出，后续同步仍会刷新文献库。
- **验证**：`test_bootstrap_does_not_refetch_catalog_for_existing_zotero_history` 修复前观察到两次摘要，修复后一次。Chrome 复核摘要先于总览、各发一次，以及之后同步在各页刷新。页面样式及数据契约沿用现有实现。

### 同日追加：译本对照入口晚出现

- **事实**：0.6.2 的导航 `display:flex` 覆盖了入口的 `hidden` 属性；0.6.3 改版后新增 `.sidebar-item[hidden]` 规则，0.6.4 沿用。对照三个版本的原始 HTML 与 CSS，WKWebView 及 Chrome 均观察到 0.6.3、0.6.4 在解除隐藏时把后方「文献导入」下推 41 像素。同一规则的增删对照复现这一变化。
- **修改**：首页渲染时只检查对齐运行时是否可用。组件不可用时查是否存在与作品关联的对齐记录，决定是否显示「只读」入口。完整文献摘要与对齐总览仍走原后台流程。提前打开作品页时在作品列表位置显示读取状态。
- **回归**：`test_translation_entry_is_visible_before_works_load` 暂停文献摘要，验证侧栏及顶栏在读取前显示入口，点击即进入作品页，加载后相邻导航保持原位。普通入口、只读入口及无组件无对齐时的隐藏状态均有覆盖。
