# Windows 发布冒烟的默认编码

2026-11-06：首次 0.6.1 发布冒烟在中文夹具编码处失败；已补发布 job 的 UTF-8 环境和回归守卫，Windows 终态仍需重跑核验。

## 事实

- 发布工作流的 Python 进程使用 cp1252，日志包含中文 JSON、模拟安装脚本和前端夹具的编码错误；全量门禁为 8 项失败、36 项错误，安装包未生成，安装生命周期检查尚未执行。证据见 [发布准备报告](../../reports/macos-release-2026-11-06.md)。
- 普通 Windows CI 已设置 `PYTHONUTF8=1`，同一产品源码的该 CI 已通过；发布工作流缺少此项。
- 新守卫先在旧工作流上失败，再在补入 job 级环境后通过；该环境也传给打包脚本及其 Python 子进程。

## 推断与边界

- 推断：初次发布冒烟的这批错误由环境差异导致。该判断以错误栈和普通 CI 的环境差异为依据，须由补齐环境后的 Windows 发布冒烟终态验证；本机 macOS 通过不替代该门禁。


## 2026-11-06 — 用户调整交付范围

- 事实：UTF-8 修复提交 `167c73a` 已通过本机全量 2,875 项（39 跳过）及远端四项 CI。第二次 Windows 发布冒烟 `42221216166` 在打包步骤运行时，用户明确要求“win云上打包不了我win电脑打包，别一直卡这里，存草稿就行”；云端运行按要求取消，Windows 安装包改由 Win 电脑后续补入。
- 边界：本轮没有完成 Windows 发布冒烟或安装生命周期验收，不把普通 Windows CI 全绿当作发布冒烟已通过；不再自行重跑云端打包。详见同一发布准备报告。
