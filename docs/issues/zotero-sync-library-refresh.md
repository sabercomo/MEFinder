# Zotero 已导入但文献库仍显示旧列表

## 2026-10-03 — 复现与修复

### 事实

- `20-search.js` 的 `fetchLibraryCatalog()` 缓存会话内文献库摘要；`invalidateLibraryCatalog()` 清空摘要、在途请求引用及列表加载标记。`10-shell.js` 进入文献库时仅在 `libraryStore.loaded` 为 false 时加载。
- 修前 `62-zotero.js` 的 `loadStatus()` 只更新设置页，不调用缓存失效入口，且只在设置页激活且任务忙碌时继续轮询。启动入口也没有启动 Zotero 状态观察。
- `/api/zotero/status` 已返回全库 `documents.linked` 及 `last_success_at`、`finished_at`；`rows` 仅含最近一趟同步，不能用于判断所有后台补交任务是否完成。
- 在临时目录读取 `6ae8107` 的原始 JS，执行 `test_import_after_leaving_settings_invalidates_existing_catalog`，失败于文献库重载次数为 0（期望 1）；同一用例对修复后源码通过。测试执行真实 Zotero 和摘要缓存 JS，模拟 API 与计时器。
- 用户提供的旧会话记录包含真实库及接口数量；本轮未重新核验这些历史计数，不将其作为当前数据结论。

### 修复

- 已导入数量或同步完成时间变化时失效共享摘要缓存。首次观察若已有导入/完成状态也失效，覆盖启动同步在首次观察前已完成的情况；数量不变的替换、题录更新和部分失败同步由完成时间变化通知。
- 文献库可见时自动重载；隐藏时标记未加载，下次进入重拉。无变化时保留缓存，不重复读取摘要。
- 首屏摘要请求结束后启动观察。设置页可见且忙碌时使用原有 1.2/3 秒间隔，其余时每 10 秒观察，覆盖离开设置页、明细没有全部 pending 任务、启动同步稍后才开始及每 30 分钟自动同步。
- 复用 `MEFinderTaskState.createLatest()`，旧响应不得回滚新观察结果或覆盖手动同步。请求失败提示错误并安排下一次观察，不清空上一次成功状态。

### 验证

`tests/test_zotero_settings_frontend.py` 覆盖新增/移除、同数量同步完成、后台补交（无 busy 明细）、首次已完成状态、稍后自动同步、设置页离开、状态请求失败、请求乱序、手动同步与启动装配入口。专项 28 项通过；Python 3.12 全量 unittest 2738 项通过（24 项环境跳过，276.083 秒），跟踪 Python 文件 Ruff(F) 零告警，两份改动 JS 的 Node 语法检查通过，前端装配指纹基线为 1516242 字节 / `1a7b6be0f3bbac086c0dad865ec99ac73847ca60c51d2ca85d866aa16c222bef`。

### 推断与限制

- 推断：旧会话中接口已含新增文献而界面仍旧的现象，与已复现的缓存遗漏一致。本轮验证了代码因果，未重跑真实 Zotero 导入操作。
- 后台刷新最长需一个 10 秒观察间隔再加本机接口及渲染耗时；暂停/失败的解析任务仍按既有导入流程处理。
