## 引用页码：页内文字就是该页印的文字

- **跨页段落拆回原页**：MinerU 会把跨页的段落整段并进前一页，导致下一页开头几行挂在上一页的页码下（库内 MinerU 页面约 55% 有此情况）。导入时现按 MinerU 保存的合并前版面记录（`layout.json`）把这些段落切回各自的印刷页，含整页续接的连续多页；证据不全的保持原样并标记，不猜。全库只读统计中，可读的 120 本 MinerU 书 90.5% 的合并块可精确拆回，92.5% 的页面核准为“页内文字即该页所印”。
- **新 engine 导入也能找到版面记录**：分段清单新增 `parser_slice_id`；旧清单经只读查询解析任务账本找回对应切片目录。
- **跨页检索窗口只接正文**：跨页句检索不再被页眉、页下注和页码隔断。
- **导出不重复拆分**：导入时已拆过的块带 `page_split` 标记，Markdown / EPUB 导出直接使用；导出重建同样支持连续多页。

## 译本对齐组件安装进度

- 模型下载在“已下载 / 总量 · 百分比”后显示下载速度与预计剩余时间（按近 20 秒速度估算，模型总量为估计值，故为“约”）。
- 独立计算运行时安装显示“第 N/4 步”（准备安装工具、创建 Python 环境、安装计算依赖、验证）与已用时间；安装工具下载阶段另有速度与剩余时间。环境、依赖与验证三步拿不到字节数，只给步骤与已用时间，不编百分比。

## MCP

- `describe_page_mapping` 去掉 `offset` 字段。引用页码即书上印的页码，PDF 页号只是文件位置，不需换算；相邻区间印刷页不连续时给出 `page_jump`（`missing` 为扫描件缺的印刷页，`null` 为页码重新起算）。
- 新增 `page_text`：`exact_pages`（页内文字已核准）、`merged_pages`（仍有未能拆回的合并）、`unchecked_pages`（尚未按版面记录核对的旧导入页）。
- 服务器说明改为“引用页即该页印的页码，不换算”。契约文件仍为 `docs/contracts/v0.5.1-mcp-v1-tools.json`（原地更新）。

## 已知限制与升级注意

- 已入库的书保留旧页面记录（`page_text` 显示为 `unchecked_pages`），需用 `python -m me_finder refresh-page-text --root <数据根> --apply`（先关闭 MEFinder）从缓存局部刷新：只替换页面文字与检索段落，书名、书目、页码映射与导入记录原样保留，页码会变的书自动跳过；刷新前自动整库备份。刷新会移除这些书的旧对齐（其位置指向旧文字），刷新后需在译本对照里重新对齐；“上次读到”位置保留。
- 解析清单里记录的旧数据根路径（Windows 盘符、旧 OneDrive 目录）现会自动改接到当前数据根，换机器或搬数据目录后仍能从缓存读取。
- 本地 MinerU 任务未保留原始版面记录，这类书无法按证据拆分，`page_text` 如实显示为未核对。
